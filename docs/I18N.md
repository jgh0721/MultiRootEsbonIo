# 다국어 지원

한국어(원어) · 영어 · 일본어를 지원한다. 설정 → 공통 → **표시 언어** 에서 바꾸고,
바꾸는 즉시 화면에 반영된다(재시작 불필요).

## 구조

| 것 | 어디 |
|---|---|
| 번역 원본 | `translations/mrst_{ko,en,ja}.ts` — **커밋한다** |
| 번역 산출물 | `<빌드>/mrst_*.qm` — `.gitignore` 로 막혀 있다. **exe 안에 임베드**된다 (`:/i18n/`) |
| 용어집 | `translations/glossary.tsv` |
| 도구 | `tools/i18n/*.py` (`tools/uv.exe` 로 실행, 추가 설치 없음) |
| 런타임 | `src/core/solLanguageManager.{hpp,cpp}` |
| 업데이터 | `updater/solUpdaterStrings.{hpp,cpp}` — Qt 를 링크하지 않아 별도 표를 쓴다 |

`mrst_ko.ts` 는 복수형 전용이다(원어라 옮길 것이 없다). 그래도 만드는 이유는
`qtbase_ko.qm` 을 실어 나르기 위해서다 — 그 덕에 한국어에서도 `QMessageBox` 의
예/아니오, `QColorDialog`, 비네이티브 저장 대화상자가 한국어로 나온다.

## `.qm` 을 exe 에 넣는 이유

`cmake/PackageRelease.cmake` 는 스테이징에 exe 2개만 복사하고 **있어야 할 파일과
있으면 안 되는 파일을 검증**한다. 느슨한 `.qm` 파일로 배포하면 개발 빌드에서는
되고 릴리스에서만 번역이 사라진다 — 그 스크립트가 막으려던 바로 그 부류의 버그다.

`qt_add_translations(... MERGE_QT_TRANSLATIONS QT_TRANSLATION_CATALOGS qtbase)` 가
Qt 자신의 번역까지 우리 `.qm` 하나로 합치므로, 배포 파일은 **한 개도 늘지 않고**
런타임 `QTranslator` 도 하나면 된다.

> 카탈로그를 `qtbase` 로 못 박은 것은 실수가 아니다. 생략하면 WebEngineCore
> 때문에 `qtwebengine` 이 딸려 오는데 Qt 6.11.1 에는 `qtwebengine_ja.qm` 이 아예
> 없어 구성할 때마다 경고가 뜬다.

## 문자열을 추가/수정했을 때

```powershell
# 1) 소스에서 문자열을 다시 수집한다 (소스 트리의 .ts 를 고친다!)
cmake --build --preset update-translations

# 2) 아직 번역되지 않은 것만 뽑는다
tools\uv.exe run --script tools\i18n\ts_export.py --lang en --tsv --only-untranslated

#    → translations\_work\en\all.tsv  (id / context / plural / note / source)
#    LLM 이나 사람이 번역해서 같은 폴더에 all.out.tsv 로 저장한다
#    형식: id<TAB>번역   (복수형은 id<TAB>단수<TAB>복수)

# 3) 되돌린다. 검증에 걸린 항목은 쓰지 않고 목록으로 알려 준다
tools\uv.exe run --script tools\i18n\ts_merge.py --lang en

# 4) 커밋 전에 확인
tools\uv.exe run --script tools\i18n\ts_lint.py --strict
```

일본어는 `--lang ja` 로 같은 절차를 밟는다. 다만 **영어를 먼저** 끝내는 편이 낫다 —
`ts_export.py` 가 일본어 청크에 한국어 원문과 영어 번역을 함께 실어 보내므로,
한국어가 주어와 조사를 생략한 자리에서 문맥을 놓치지 않는다.

사람이 손볼 때는 Qt Linguist 를 그대로 쓸 수 있다:

```powershell
& "D:\Qt\6.11.1\msvc2022_64\bin\linguist.exe" translations\mrst_ja.ts
```

`ts_merge.py` 는 쓰고 나서 `lconvert` 로 정규화한다. 이걸 건너뛰면 ElementTree 의
출력 형식이 Qt 와 달라서, 사람이 Linguist 로 한 번 저장하는 순간 파일 전체가
diff 로 뜬다.

## `type="unfinished"` 를 남겨 두는 이유

LLM 이 채운 번역도 `unfinished` 그대로 둔다. qttools 의 `releasehelper.cpp` 는
**"번역이 있으면서 unfinished 인"** 항목만 검사하므로, finished 로 표시하면
`lrelease -fail-on-invalid` 가 아무것도 검사하지 않는다. unfinished 라도 번역
텍스트가 있으면 `.qm` 에 그대로 들어가 사용자에게는 차이가 없고, Linguist 의
"미완료" 필터가 그대로 사람 검수 대기 목록이 된다.

사람이 검수를 마친 항목만 Linguist 에서 finished 로 바꾼다. 진행률이 곧 검수율이다.

**`-fail-on-unfinished` 는 절대 주지 않는다.** 주면 빌드가 통째로 막힌다.

## 검증

같은 규칙이 세 곳에서 돈다. 규칙 자체는 `tools/i18n/_tslib.py` 의 `check()` 와
`tests/tst_Translations.cpp` 에 있다.

| 어디 | 언제 | 무엇 |
|---|---|---|
| `ts_merge.py` | 되돌릴 때 | 위반 항목은 **쓰지 않고** 재번역 대기열로 |
| `ts_lint.py --strict` | 커밋 전 | 위반 + 미번역 |
| `mrst_tests` | `ctest` 마다 | 위반 + `.qm` 임베드 + qtbase 병합 회귀 |

검사 항목: `%1..%9` 인덱스별 개수 / `%n` 보존 / 앞뒤 공백 완전 일치 / 개행 개수 /
니모닉 `&` 개수 / 파일 필터 `;;`·글롭 / HTML 태그 / **번역문에 한글 잔존** /
기호·단위 원문 유지 / 길이 폭주(원문 ×3).

```powershell
cmake --preset Debug-Tests
cmake --build --preset Debug-Tests
ctest --preset Debug-Tests
```

## 번역 관례

**영어** — Sentence case. 니모닉은 인라인(`파일(&F)` → `&File`, `종료(&X)` → `E&xit`).
한국어의 `(&X)` 접미 표기를 그대로 옮기는 것이 가장 흔한 실수다.

**일본어** — 니모닉은 괄호형을 유지하고 **문자도 그대로** 둔다(`終了(&X)`).
그러면 메뉴 안에서 중복이 새로 생길 수 없다. ASCII·`%1`·단위는 반각, 콜론도 반각
(폼 라벨 정렬이 틀어진다). `%1` 주위에 공백을 새로 넣지 않는다. 사용자에게 말하는
문장은 です・ます, 라벨과 버튼은 体言止め.

용어는 `translations/glossary.tsv` 를 따른다. 새 용어를 정하면 거기에 적는다 —
`ts_export.py` 가 모든 청크에 그 표를 함께 실어 보낸다.

## 번역하면 안 되는 것

코드에 주석으로 이유를 적어 두었다. 요약:

- **`solVirtualProjectMgr.cpp` 의 `"문서"`** — 자동 생성 `conf.py` 의
  `project = "%1"` 에 그대로 들어가는 **파이썬 소스**다. 따옴표나 역슬래시가 섞이면
  Sphinx 빌드가 통째로 실패한다
- **`TextLexerRegistry` 의 `displayName`** — `m_profileIndexByName` 의 키이고
  도구모음 콤보의 `currentTextChanged` 가 그 텍스트를 그대로 되돌려 준다
- **`solSphinxDiagnostics.cpp` 의 `WARNING|ERROR|CRITICAL` 정규식** — 외부 프로세스
  출력을 파싱한다. 같은 이유로 **서브프로세스에 `LANG`/`LC_ALL` 을 주입하지 말 것**
- 기호(`⫶` `☰` `■` `✕`), 단위 접미사(`" pt"` `" MB"` `" ms"`), 파일 글롭 패턴
- `updater.log` 의 로그 문장 — 개발자용 기록이다. 사용자가 보내 온 로그를 읽을 때
  번역판을 맞춰 볼 이유가 없다

## 언어를 하나 더 늘리려면

1. `CMakeLists.txt` 의 `qt_standard_project_setup(I18N_TRANSLATED_LANGUAGES ...)` 에 코드 추가
2. `src/core/solLanguageManager.cpp` 의 `supportedCodes()` 와 `nativeName()` 에 추가
3. `LanguageManager::systemLanguage()` 의 `switch` 에 `QLocale::언어` 추가
4. `tests/tst_Translations.cpp` 의 `kLanguages` / `tools/i18n/ts_lint.py` 의 `LANGS`
5. `updater/solUpdaterStrings.{hpp,cpp}` 의 `UiLang` 과 표 (업데이터는 별개다)
6. `cmake --build --preset update-translations` 후 번역

## 런타임에서 벌어지는 일

`main()` 이 위젯을 만들기 **전에** `LanguageManager::installAtStartup()` 을 부른다
(MainWindow 생성자가 이미 `tr()` 을 수십 번 부르므로 그보다 늦으면 첫 화면이 원문으로 굳는다).

설정에서 언어를 바꾸면 `setLanguage()` → `installTranslator()` → Qt 가
`QEvent::LanguageChange` 를 **모든 최상위 위젯에 post** → 각 `changeEvent()` 가
자기 화면을 다시 칠한다. 구현한 곳은 넷뿐이다:

- `MainWindow::changeEvent` → `retranslateUi()`
- `QSettingsDialog::changeEvent` → `buildPages()` (페이지를 통째로 다시 만든다)
- `FindReplaceWidget::changeEvent` → `retranslateUi()`
- `QAboutDialog::changeEvent` → `retranslateUi()`

### 손대면 안 되는 두 가지

**메뉴바를 재생성하지 말 것.** `menuBar()->clear()` 는 QMenu 객체를 지우지 않아
옛 QAction 이 MainWindow 자손으로 살아남는다. `ApplyShortcutsToActions()` 가
`findChildren<QAction*>()` 로 옛것과 새것 모두에 같은 단축키를 걸면 Qt 는 모호한
단축키로 보고 **둘 다 발동시키지 않는다** — 언어를 한 번 바꾸면 Ctrl+S 가 죽는다.
문자열은 `MainWindow::retranslateMenus()` 한 곳에만 두고 `setText()` 로 갈아 끼운다.

**앱 전역 eventFilter 에서 `LanguageChange` 를 처리하지 말 것.** 그 필터는 모든
위젯의 모든 이벤트를 보므로 위젯 수만큼 호출되고, `updateViewerToolBar()` 가 지금
이벤트를 받고 있는 툴바를 `delete`(=`deleteLater` 가 아니다) 해 버린다.

### 일부러 남겨 둔 것

상태 표시줄의 임시 메시지(수 초 뒤 사라진다), 이미 열린 탭의 "제목없음"
(`setDisplayTitle()` 로 굳는다 — 새 탭부터 새 언어), `로그` 탭에 이미 쌓인 줄
(시각이 찍힌 기록이라 다시 쓰면 이력이 망가진다).

**프리뷰와 LSP 는 언어 전환 시 아무것도 하지 않는다.** 건드리면 수십 초짜리
재빌드나 LSP 세션 끊김만 생긴다.

## 업데이터

`mrst_updater.exe` 는 **Qt 를 링크하지 않는다**(Qt6Core.dll 을 로드하면 자기가
교체해야 하는 파일을 스스로 잠근다). 그래서 문자열을 세 부류로 가른다.

| 부류 | 처리 |
|---|---|
| `log.line()` 로그 | 번역하지 않는다 |
| `log.setFailure()` 실패 사유 | `FailureId` 식별자만 `result.ini` 에 쓰고, **앱**의 `UpdateInstaller::describeFailure()` 가 문장을 만든다 |
| `MessageBoxW` 4개 | `solUpdaterStrings.cpp` 의 3언어 표 |

`--lang` 같은 인자는 만들지 않았다. 앱이 실행할 때 업데이터는 창을 하나도 띄우지
않고(결과는 log + result.ini), 사람이 직접 실행하는 경로(인자 없음 / `--rollback`)
에는 앱이 개입하지 않는다 — 어느 쪽에서도 값을 받지 못하는 죽은 인자가 된다.
대신 `GetUserDefaultUILanguage()` 를 본다(`GetUserDefaultLocaleName()` 이 **아니다**
— 그쪽은 "국가 또는 지역 > 형식" 설정이라 한국에서 영어판 Windows 면 ko-KR 이 나온다).

`describeFailure()` 는 **모르는 값을 그대로 통과**시켜야 한다. 교체 직전에 도는
업데이터는 항상 구버전이라, 예전 형식(완성된 한국어 문장)이 계속 들어온다.
