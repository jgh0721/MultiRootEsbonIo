====================
회의록: 프리뷰 정책
====================

이 파일도 어느 프로젝트에도 속하지 않습니다. 워크스페이스 루트 아래 ``notes``
폴더에 있고, 위로 올라가며 ``conf.py`` 를 찾아도 나오는 것이 없기 때문입니다.
편집기는 이 파일 하나만을 위한 최소 프로젝트를 임시 디렉터리에 만들어 빌드합니다.

참석
====

:일시: 2026-03-04
:참석: 렌더링, 도구, 문서
:안건: 프리뷰가 바깥으로 나가는 요청을 허용할 것인가

논의
====

프리뷰는 실제 Sphinx 빌드 결과를 그대로 보여 줍니다. 그 말은 문서가 CDN 에서
스크립트를 받아 오도록 쓰여 있으면 프리뷰도 그 요청을 보낸다는 뜻입니다. 도표를
그려 주는 확장들이 대개 그렇게 동작합니다.

편한 쪽과 안전한 쪽이 갈리는 자리입니다. 그려지는 편이 당연히 편하지만, 사내
장비에서 문서를 여는 것만으로 바깥으로 요청이 나가는 것은 설명하기 어려운
동작입니다. 특히 그런 요청이 언제 나가는지 사용자가 알 수 없다는 점이 문제였습니다.

.. important::

   결론: 기본값은 허용, 설정에서 끌 수 있게. 끄면 도표는 원본 텍스트 그대로
   남습니다. 조용히 빈 칸이 되지 않는 것이 중요합니다.

정하지 못한 것
==============

* 프로젝트마다 따로 설정할 수 있어야 하는가. 지금은 앱 전체 설정 하나입니다.
* 허용 목록 방식이 쓸모가 있는가. 도메인을 적어 두는 방식은 확장이 어느 도메인을
  쓰는지 사용자가 알아야 해서, 아는 사람에게만 쓸모가 있습니다.

.. note::

   다음 회의까지 도구 팀이 실제로 어떤 도메인들이 호출되는지 목록을 뽑아 오기로
   했습니다.
