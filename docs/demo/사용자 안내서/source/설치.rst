내려받아 풀기
=============

|제품| 은 설치 관리자 없이 압축 파일 하나로 배포합니다. 쓰기 권한이 있는 아무
폴더에나 풀고 한 번 실행하면 캐시 디렉터리를 스스로 만들고 끝입니다. 등록할
서비스도, 셸 확장도, 레지스트리에 남기는 항목도 없습니다. 폴더를 지우면 아무것도
남지 않는다는 뜻이기도 합니다. 이것은 포장이 게을러서가 아니라 일부러 건 제약인데,
이 엔진이 주로 쓰이는 자리가 밤마다 이미지를 다시 굽는 작업용 장비이기 때문입니다.
그런 장비에서는 작업 폴더 밖에 쓴 것은 아침이면 사라져 있고, 관리자 권한이 필요한
것은 아예 쓸 수가 없습니다.

.. code-block:: powershell
   :caption: 풀고 처음 실행하기
   :linenos:

   Expand-Archive orca-3.2.0-win64.zip -DestinationPath C:\tools\orca
   cd C:\tools\orca
   .\orca.exe --version
   .\orca.exe --self-check

환경 점검
=========

``--self-check`` 는 무엇보다 먼저 돌려 볼 만합니다. 엔진이 시작할 때 지나가는
경로를 그대로 따라가되 계속 진행하는 대신 무엇을 찾았는지 출력하기 때문에, 드라이버
기능이 빠진 장비가 세션 시작 3분 뒤 크래시가 아니라 한 줄짜리 메시지로 그 사실을
알려 줍니다.

.. code-block:: text
   :emphasize-lines: 4,5

   orca 3.2.0 (win64, msvc 19.44)
   adapter     : NVIDIA RTX A2000        12288 MB
   backend     : d3d12 (feature level 12_1)
   tracing     : enabled -> traces/
   shader cache: MISS (cold, will rebuild on first frame)
   result      : ok

강조된 두 줄이 평범한 실행과 이상한 실행을 가르는 자리입니다. 셰이더 캐시가 비어
있으면 첫 프레임이 오래 걸리는 이유가 설명되고, 추적이 꺼져 있으면 프로파일러에
아무것도 안 나오는 이유가 설명됩니다.

자주 막히는 곳
==============

.. danger::

   ``trace.path`` 를 네트워크 드라이브로 지정하지 마세요. 추적 기록은 프레임마다
   쓰이므로, 지연이 한 번만 튀어도 그 프레임의 예산이 통째로 날아갑니다.

.. tip::

   ``--budget strict`` 는 지속 통합 작업에서만 쓰는 것이 좋습니다. 개발 중에는
   예산을 넘겼다는 사실만 알면 충분하고, 그때마다 멈추면 일이 되지 않습니다.

:term:`프레임 예산`, :term:`셰이더 캐시`, :term:`추적 기록` 같은 말은
:doc:`용어집` 에 정의해 두었습니다.
